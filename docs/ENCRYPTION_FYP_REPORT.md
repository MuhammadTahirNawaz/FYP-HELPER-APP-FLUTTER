# AES Encryption — FYP Report Paragraph (copy-paste)

FYP Helper implements AES-256 in CBC mode (via the Dart `encrypt` package) as a coursework security demonstration to protect sensitive user profile data—specifically phone numbers—before persistence in Firebase Realtime Database. Plaintext phone values are encrypted on the client immediately prior to write operations in `UserProfileService`, stored under the `phoneEncrypted` field, and decrypted only when an authorized role (e.g. supervisor reviewing student contact details) reads the profile. Cryptographic key material is not hardcoded at runtime: on first launch the app seeds a 32-byte secret key and 16-byte initialization vector (IV) into `flutter_secure_storage`, which uses the platform keystore (Android EncryptedSharedPreferences / Windows credential vault), and all subsequent encrypt/decrypt operations load key and IV from that secure vault. Heavy encrypt/decrypt work is offloaded to a background isolate via Flutter’s `compute()` API and timed with a custom `Profiler` for performance observability during development. This design satisfies the rubric’s encryption/decryption requirement as an understandable proof-of-concept; in a production system the same architecture would source rotating keys from a remote Key Management Service (KMS) or Firebase Cloud Functions rather than client-seeded defaults, and would additionally enforce field-level access exclusively through hardened Firebase Security Rules.
